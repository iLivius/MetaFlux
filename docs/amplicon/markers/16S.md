# 16S rRNA (bacteria and archaea)

16S is the default marker: `config/config.yaml` ships with `amplicon.type: 16S`.

!!! info "What this page is, and what it is not"

    This page is documentation. It is not a settings file, it does not sit "above" or
    "below" `config/config.yaml`, and nothing written here is in force on your machine.
    Every YAML block below is an illustration of what to put in **your own** config.

    Two real files decide how a 16S run behaves, and they do not overlap:

    - **`workflow/markers/16S.yaml`** — the *marker pack*. Facts about the marker:
      which databases to use, that the amplicon length is measured by in-silico PCR
      against SILVA, that Metaxa2 is the region extractor, that the rank model has seven
      slots (the last of which only the separate species database can fill). Data, not
      knobs. You normally never touch it.
    - **`config/config.yaml`**, plus any run config merged on top — the *choices about
      your experiment*: primers, expected length, truncation, taxon filter, paths.

    The pack is loaded into its own namespace and is never merged into the config, so
    almost nothing can arrive from both. The exceptions sit under `references:`. A
    database path there wins over the pack default — that is how you point at a shared
    copy of SILVA instead of downloading your own — and `references.silva.release`
    replaces the pack's default SILVA release. The full picture is in [which file a setting actually comes from](../../reference/configuration.md#which-file-a-setting-actually-comes-from).

## Setting up a run

Set `type: 16S` and supply the forward and reverse primer FASTAs for the region
amplified. The rest of the block below reproduces the shipped defaults for the keys you
are most likely to want to set on a 16S run — not every key the run touches; `cutadapt`,
`trunc_len` and `length_filter` are covered further down and in the
[configuration reference](../../reference/configuration.md). You do not need to copy any
of it into your own config to get these values, since the template already provides them.
The two exceptions are `keep` and `discard`: those ship commented out, so the values
shown are the recommended 16S starting point rather than something already in effect.

```yaml
amplicon:
  type: 16S

  primers:
    fwd: /path/to/fwd_primer.fasta
    rev: /path/to/rev_primer.fasta
    orientation: fixed            # fixed | mixed

  expected_length: auto           # in-silico PCR against SILVA
  probe_length_stat:
    16S: p95                      # which statistic of the probe distribution to use
  min_overlap: 12                 # bp of R1/R2 overlap the truncLen pair must preserve

  extraction:
    enabled: true                 # Metaxa2

  taxonomy:
    method: sintax                # rdp | sintax
    min_boot: 80                  # rdp only
    sintax_cutoff: 0.8            # sintax only
    try_rc: true                  # rdp only
    silva_other: verbatim         # SILVA 144 only: verbatim | strip
    filter:
      enabled: true
      keep:    [k__Bacteria, k__Archaea]          # recommended, ships commented out
      discard: [o__Chloroplast, f__Mitochondria]  # recommended, ships commented out
      discard_min_support: 50                     # best-hit check for discard; null = off
      organelles: metaxa2                         # drop what Metaxa2 calls organelles; off = keep
```

!!! note

    `amplicon.probe_length_stat.16S` must be present for a 16S run, whether or not
    `expected_length` is `auto` — MetaFlux checks the key at startup and exits with a
    message naming it if it is missing. The shipped `config/config.yaml` already has it.

## Reference databases

16S is classified against SILVA. MetaFlux ships two SILVA releases: **SILVA 144**, the
default, and the previous release, **SILVA 138.2**, which a run can still choose.
None of the files needs to be listed in the config: the marker pack carries the file
names, download URLs and md5 checksums, and MetaFlux fetches what the run needs on
first use into `references.refdb_root` (default `refdb`), where it stays cached for
later runs. Every download is checked against its md5 before anything uses it; on a
mismatch the file is deleted and the run stops.

### SILVA 144 (default)

The DADA2 files for SILVA 144 are built and published by the SILVA team itself
([arb-silva.de](https://www.arb-silva.de/archive/release_144/DADA2/1.36.0/SSU)); the
138.2 files come from the DADA2 author's own Zenodo record (below). MetaFlux downloads
the 144 files from the release folder, `release_144`, rather than from
"current-release", so the address does not change when SILVA 145 comes out.

| Pack symbol | Path under `refdb_root` | What it is | How it arrives |
|---|---|---|---|
| `silva_train_raw` | `silva/silva_nr99_v144_toGenus_trainset.fa.gz` | the training set exactly as SILVA publishes it, seven ranks; also the in-silico PCR substrate | download from SILVA (rule `fetch_silva_train_raw`) |
| `silva_train` | `silva/silva_nr99_v144_toGenus_6rank_other-verbatim_trainset.fa.gz` | the same sequences with the Kingdom rank removed: RDP training set | built locally (rule `convert_silva_train`) |
| `silva_kingdom_map` | `silva/silva_nr99_v144_kingdom_map_other-verbatim.tsv` | which kingdom each phylum belongs to | built by the same rule, from the same file |
| `silva_sintax` | `silva/silva_nr99_v144_6rank_other-verbatim_sintax.fa.gz` | SINTAX database for VSEARCH | built locally from `silva_train` (rule `convert_silva_sintax`) |
| `silva_species` | `silva/silva_v144_assignSpecies.fa.gz` | `addSpecies` reference (16S, `rdp` only) | download from SILVA (rule `fetch_silva_species`) |

With `amplicon.taxonomy.silva_other: strip` (see below) the three built files carry
`other-stripped` instead of `other-verbatim` in their names, so the two settings never
share a cached file.

The headers look like this — the differences matter for what each step can return:

```text
silva_train_raw  >Bacteria;Pseudomonadati;Pseudomonadota;Gammaproteobacteria;Pseudomonadales;Pseudomonadaceae;Pseudomonas;
silva_train      >Bacteria;Pseudomonadota;Gammaproteobacteria;Pseudomonadales;Pseudomonadaceae;Pseudomonas;
silva_sintax     >1;tax=d:Bacteria,p:Pseudomonadota,c:Gammaproteobacteria,o:Pseudomonadales,f:Pseudomonadaceae,g:Pseudomonas
silva_species    >AM889137.2051270.2052798 Neisseria meningitidis
```

The training set is a *toGenus* release: its lineages stop at genus, with no rank
prefixes and no species field. That single fact explains both the `addSpecies` step
and the rank depth of the two taxonomy methods, below.

### The Kingdom rank: removed for classification, restored next to it

SILVA 144 re-annotated all prokaryote sequences, using LPSN as the main source of
names, and added a **Kingdom** rank between Domain and Phylum: *Bacillati*,
*Pseudomonadati*, *Fusobacteriati* and *Thermotogati* for Bacteria; *Methanobacteriati*,
*Thermoproteati*, *Nanobdellati* and *Promethearchaeati* for Archaea. Its lineages
therefore have seven ranks where 138.2 had six.

MetaFlux's 16S rank model writes the domain in the first slot (`k__Bacteria`), then
`p__` to `g__`, then `s__`. Fed the seven-rank file directly, every name would land one
slot too deep: genus in the species slot, `Chloroplast` at family, `Mitochondria` at
genus, and the usual `o__Chloroplast` / `f__Mitochondria` filter tokens would silently
stop matching anything. So rule `convert_silva_train` removes the Kingdom field before
any classifier sees the file. The sequences are not touched, only the headers. The
rule also refuses a file that does not have the shape of a SILVA 144 toGenus file (a
138.2 file, a toSpecies file, a broken download) rather than guess. Both taxonomy
methods, the length probe and every table downstream then work exactly as they did
with 138.2, and the filter tokens keep their meaning.

The kingdom is not lost. In SILVA 144 every phylum but one (the placeholder *Incertae
Sedis*, below) sits under a single kingdom, so the kingdom can be put back from the
phylum. Rule `convert_silva_train` therefore also writes a phylum → kingdom table
(`silva_kingdom_map`), and after classification rule `restore_kingdom` writes
`06.taxonomy/taxonomy_lineage_full.tsv`: one row per ASV with `Domain`, the restored
`Kingdom`, `Phylum` … `Species`, the full SILVA-style lineage
(`Bacteria;Pseudomonadati;Pseudomonadota;…;Pseudomonas;`) and a `kingdom_note` column.
The three usual tables are not changed. The kingdom is left empty, with the reason in
`kingdom_note`, when:

- the ASV was classified to domain only — the kingdom is read off the phylum, and
  Bacteria alone spans several kingdoms;
- the phylum is SILVA's placeholder *Incertae Sedis*, the one phylum that occurs under
  more than one kingdom (1,506 reference sequences under *Pseudomonadati*, 5 under no
  named kingdom);
- the ASV is eukaryotic: the DADA2 file carries eukaryotes at domain level only.

A handful of phyla have no named kingdom in SILVA 144 (e.g. *Candidatus
Korarchaeota*); for those `taxonomy_lineage_full.tsv` writes `Incertae Sedis`, as SILVA
does, and says so in `kingdom_note`.

### The `--other` suffix (`amplicon.taxonomy.silva_other`)

SILVA 144 writes `X--other` for a clade that does not contain the nomenclatural type of
taxon *X*, but whose sequences SILVA still considers part of *X* — for example
`Bacillaceae--other` next to `Bacillaceae`, or `Bradyrhizobium--other` next to
`Bradyrhizobium`. About 40% of the reference sequences carry it somewhere in their
lineage. One setting decides what MetaFlux does with it:

| `silva_other` | Effect |
|---|---|
| `verbatim` (default) | Names are kept exactly as SILVA writes them. The keep/discard filter treats `X--other` as `X` (so `g__Bradyrhizobium` also removes `g__Bradyrhizobium--other`), and so does the genus check of `addSpecies`; the species is written with the plain genus (`g__Lactobacillus--other;s__Lactobacillus iners`). |
| `strip` | The suffix is removed from every name before the classifier is trained, so *X* and *X--other* become one taxon. |

In practice the two settings give the same lineages apart from the suffix itself,
except that `strip` can give a few more ASVs a genus, because the classifier no longer
has to choose between two labels for one genus.

SILVA 144 also merges a few intermixed taxa into one label joined by `+`, each part with
its own suffix: `Enterobacter--other+Klebsiella--other`, `Rubrivivax--other+Ideonella--other`
(about 0.2% of the reference sequences). MetaFlux keeps these labels as they are:
neither the filter nor `addSpecies` splits them, so a token `g__Klebsiella` does not
remove an ASV labelled `g__Enterobacter--other+Klebsiella--other`. Add the full label
as a token if you need to.

### Choosing SILVA 138.2

To run on the previous release, add this to the run config:

```yaml
references:
  silva:
    release: "138.2"
```

The 138.2 files are Benjamin Callahan's DADA2 build
([Zenodo 14169026](https://doi.org/10.5281/zenodo.14169026)), already six ranks, so
there is no conversion step, no kingdom table and no `taxonomy_lineage_full.tsv`;
`silva_other` has no effect. They keep their own file names, so switching back and forth never overwrites
the other release's files:

| Pack symbol | Path under `refdb_root` | How it arrives |
|---|---|---|
| `silva_train` | `silva/silva_nr99_v138.2_toGenus_trainset.fa.gz` | download from Zenodo |
| `silva_species` | `silva/silva_v138.2_assignSpecies.fa.gz` | download from Zenodo |
| `silva_sintax` | `silva/silva_nr99_v138.2_sintax.fa.gz` | built locally from `silva_train` |

### Using a shared copy

Apart from the release, an entry under `references:` in the run config is needed only
to relocate a file that already exists elsewhere, for instance on a shared filesystem. Under SILVA 144, relocate
the files that belong together, so the training set, its kingdom table and its SINTAX
build always come from the same conversion:

```yaml
references:
  refdb_root: refdb
  silva:
    train_raw:   /shared/dbs/silva_nr99_v144_toGenus_trainset.fa.gz
    train:       /shared/dbs/silva_nr99_v144_toGenus_6rank_other-verbatim_trainset.fa.gz
    kingdom_map: /shared/dbs/silva_nr99_v144_kingdom_map_other-verbatim.tsv
    sintax:      /shared/dbs/silva_nr99_v144_6rank_other-verbatim_sintax.fa.gz
    species:     /shared/dbs/silva_v144_assignSpecies.fa.gz
```

## Amplicon length probe (`probe_mode: pcr`)

SILVA sequences are whole 16S genes (the SILVA 144 files are trimmed to the gene
itself, 138.2 still carries some flanking sequence), so the length of the amplicon the
primers actually produce has to be worked out rather than read off the database. The
`amplicon_probe` rule does an in-silico PCR with two Cutadapt passes over SILVA's
training set as downloaded (`silva_train_raw` on SILVA 144, `silva_train` on 138.2):

1. keep the reference sequences in which the forward primer matches, trimming it and
   everything upstream of it (`-g file:<fwd> --discard-untrimmed`);
2. of those, keep the ones in which the reverse complement of the reverse primer
   matches, trimming it and everything downstream
   (`-a file:<rev_rc> --discard-untrimmed --minimum-length 30`).

Neither match is anchored, and that is the point: SILVA holds whole 16S genes, so the
primers bind *inside* them. Anchoring to the ends would match nothing. Each pass strips
the flanking gene sequence the primers would never have amplified, so what survives both
is the amplicon body itself. Primer mismatches are tolerated at
`amplicon.cutadapt.max_error_rate` (default `0.2`).

Chloroplast, mitochondrial and eukaryote references are then left out of the length
statistics (marker pack field `probe_exclude_taxa`). Bacterial primers amplify organelle
SSU in silico too, often with long insertions, but those are not what a 16S survey
measures, and the taxon filter removes them from the results anyway. SILVA 144 holds
about eight times more organelle sequences than 138.2, enough to drag the statistic
along: for 799F/1175R, p95 is 397 bp with them and 386 bp without. With 138.2 it is
384 bp either way. The amplicons FASTA still contains every product.

The rule then writes the length distribution — `n_amplicons`, `min`, `q1`, `median`,
`q3`, `p95`, `p99`, `max`, `mean`, `stdev`, plus `excluded_taxa` and `n_excluded` — to a
JSON file in the project-level cache:

```text
refdb/cache/probe_16S_silva_v144_toGenus_excl-chloroplast-eukaryota-mitochondria_<primer_hash>.json
refdb/cache/probe_16S_silva_v144_toGenus_excl-chloroplast-eukaryota-mitochondria_<primer_hash>.amplicons.fa.gz
```

The excluded lineages are part of the name, so a probe computed before v2.5.0 (or with
a different list) is never reused by mistake.

`<primer_hash>` is the first 12 hex characters of a SHA-256 over the two primer files.
Different primers give a different filename, so the probe re-runs; the same primers
hit the cache, which lives inside the repository and therefore survives across runs
and across output directories.

Two steps consume the probe:

- **`pick_trunclen`** takes `expected_length` from the statistic named in
  `probe_length_stat.16S` (default `p95`) and uses it in the overlap constraint.
- **`dada_length_filter`** builds its ASV length window as
  `[q1 − window_margin, p95 + window_margin]`, with `window_margin` defaulting to 50 bp.

The probe only runs when `expected_length: auto`. A fixed integer or a `[min, max]`
range skips it entirely.

!!! warning

    If no reference sequence carries both primers, the probe stops with an error rather
    than returning an empty distribution. The usual causes are a primer written in the
    wrong orientation for the database, or a degenerate primer that was collapsed to a
    single consensus sequence before being written to the FASTA — keep the IUPAC
    ambiguity codes, Cutadapt matches them. A low `cutadapt.max_error_rate` on a
    mismatch-tolerant primer has the same effect.

## Truncation

16S uses the standard quality-based truncation picker: `truncLen` is cut just before the
position where the aggregated per-base lower quartile first falls below
`trunc_len.q_threshold`, subject to keeping the pair mergeable —

```text
truncR1 + truncR2 >= expected_length + min_overlap
```

— with `trunc_len.resolve_policy` deciding what happens when quality and overlap
disagree.

Three checks run in a fixed sequence. First, a coverage gate caps each sample at the
length `trunc_len.min_read_coverage_pct` (95%) of its reads still reach, so the quality
search cannot pick a position most reads never get to. Only then is the quality
threshold applied, and only then the overlap constraint. See
[Amplicon length and truncation](../length-and-truncation.md) for the full picture, and
[Troubleshooting](../../troubleshooting.md) for what a run looks like when the cut still
lands past the real read length.

## Region extraction with Metaxa2

With `extraction.enabled: true` (the default), the `target_extract` rule runs
[Metaxa2](https://microbiology.se/software/metaxa2/) over the ASV sequences to keep
only the part of each ASV that is genuinely small-subunit rRNA. Anything that flanks
it — primer remnants, chimeric tails, non-ribosomal carry-over — is trimmed away, so
the ASV lengths that reach the length filter are directly comparable to the probe
distribution measured on SILVA.

| | |
|---|---|
| Input | `05.dada2/seqs.fasta` and `05.dada2/seqtab_head_names.txt`, from `dada_seqtab` |
| Command | `metaxa2 -t all --fasta T --table T --plus T --silent T` |
| Output | `05.dada2/seqs_extracted.fasta`, `05.dada2/seqtab_extracted_head_names.txt`, `05.dada2/metaxa2_extraction.results.txt`, `05.dada2/metaxa2_origin.tsv` |
| Raw tool output | kept under `05.dada2/metaxa2/` for inspection |
| Consumed by | `dada_length_filter`; `assign_taxonomy` reads `metaxa2_origin.tsv` |

`-t all` means all domains are scanned and every extracted sequence is kept.
Metaxa2 is not used to decide what is bacterial: that decision is made later, by the
taxon filter, on the classified lineage. The filter does use one of Metaxa2's calls,
the organelle one: ASVs that Metaxa2 places in mitochondria or chloroplast are removed
(`filter.organelles`, below). ASVs Metaxa2 cannot extract are dropped from
both the FASTA and the count table, and the drop is reported in the rule log.

For 16S the pre- and post-extraction length distributions usually look almost the
same, because a clean 16S amplicon is SSU from end to end. Both are plotted in
`stats/dada2/asv_length_hist.png`, which makes an unexpected difference easy to spot.

### Metaxa2 reports origin twice, and only the second answer is the real one

The organelle filter uses the second answer only, collected per ASV in
`05.dada2/metaxa2_origin.tsv`. The difference matters most when you open the Metaxa2
files yourself to ask how much chloroplast and mitochondrial carry-over a run had,
because the raw output under `05.dada2/metaxa2/` answers that question twice and the
two answers disagree badly.

**First pass — the HMM screen.** Metaxa2 begins by sliding profile HMMs along each
sequence to decide, cheaply, whether it is small-subunit rRNA at all and where the
gene starts and stops. The job of this pass is to *find* the rRNA and mark its edges,
not to identify it. Its verdict is the single letter in column 3 of
`seqs.extraction.results` (`B`, `A`, `E`, `C`, `M`, `O` for bacteria, archaea,
eukaryota, chloroplast, mitochondria, other) and the block of `seqs.summary.txt`
headed *"SSU rRNA sequences by preliminary origin"*. Metaxa2's own choice of word —
preliminary — is the warning.

**Second pass — the BLAST refinement.** The extracted regions are then aligned
against Metaxa2's reference database and classified on the alignment. This is the
result worth quoting. It is what lands in `seqs.taxonomy.txt`, in the per-origin
FASTAs (`seqs.bacteria.fasta`, `seqs.mitochondria.fasta`, and so on), and in the
block of `seqs.summary.txt` headed *"Number of SSU rRNA sequences assigned to each
origin"*.

The distance between them is not a rounding difference. On the 16S test set, of the
231 ASVs Metaxa2 recognised as SSU rRNA:

| Origin | First pass, HMM screen | Second pass, after BLAST |
|---|--:|--:|
| Bacteria | 70 | 199 |
| Chloroplast | 56 | 0 |
| Mitochondria | 105 | 28 |
| Uncertain | — | 4 |

Taken from the first pass, this library reads as 45% mitochondrial and 24%
chloroplast — a sample swamped by plant material, and a result that would send you
looking for a problem with the primers. Taken from the second, it is 86% bacterial
with no chloroplast at all.

The second reading is the correct one, and the disagreement is expected rather than a
malfunction. Chloroplasts and mitochondria descend from free-living bacteria and
their SSU genes still look bacterial, so the organellar HMM profiles and the
bacterial ones overlap heavily. A fast profile scan cannot separate them; an
alignment against full-length references can. The screen is deliberately permissive
because its purpose is to avoid missing rRNA, not to name it.

!!! note "These are ASV counts, not read counts"

    Every number above counts distinct sequences. A run can be 12% mitochondrial by
    ASV and a very different figure by abundance, since organellar ASVs are often
    numerous but individually rare, or the reverse in a root or leaf sample. To weight
    by reads, use `06.taxonomy/asv_table_unfiltered.txt`: it has Metaxa2's call
    (`metaxa2_origin`) next to the per-sample counts of every ASV, the removed ones
    included (see
    [the table with everything](../taxon-filter.md#the-table-with-everything-asv_table_unfilteredtxt)).
    `asv_table.txt` will not do, because the organelle filter has already removed the
    ASVs Metaxa2 calls mitochondria or chloroplast.

## Taxonomy

`amplicon.taxonomy.method` picks one of two classifiers. Both read the
length-filtered ASVs (`05.dada2/seqs_lenfilt.fasta` plus the matching
`seqtab_lenfilt_head_names.txt`), both apply the same taxon filter, and both write the
same four tables into `06.taxonomy/`: the three filtered ones and
`asv_table_unfiltered.txt`, which lists every ASV with Metaxa2's call and what the filter
did to it.

| | `rdp` | `sintax` |
|---|---|---|
| Tool | DADA2 `assignTaxonomy`, then `addSpecies` | `vsearch --sintax` |
| Reference | `silva_train` + `silva_species` | `silva_sintax` |
| Confidence setting | `min_boot: 80` | `sintax_cutoff: 0.8` |
| Reverse complement | `try_rc: true` | `--strand both`, always |
| Deepest rank returned | Species, as a binomial | Genus |
| Conda environment | `workflow/envs/taxonomy.yaml` | `workflow/envs/vsearch.yaml` |
| Reproducibility | fixed by `amplicon.seed`, apart from DADA2's random tie-breaking (rare, see [Troubleshooting](../../troubleshooting.md)) | fixed by `amplicon.seed`, at any thread count |

The RDP path classifies the *unique* ASV sequences and then expands the result back
so every ASV ID gets its own row — extraction can leave two ASVs with an identical
trimmed sequence, and this keeps them from being classified twice.

VSEARCH SINTAX needs about 2–3 GB regardless of how many ASVs are in the table, which
makes it the practical choice on large runs. With `amplicon.seed` fixed, its bootstrap
confidence comes out the same at any thread count, because VSEARCH 2.32, the version
MetaFlux uses from v2.5.0 on, gives every ASV its own random stream.

### The species step (16S only)

`silva_train` stops at genus, so the RDP path alone cannot name a species. 16S is the
only marker whose pack declares a `taxonomy_species_db`, and for it the rdp branch of
`assign_taxonomy` runs DADA2's `addSpecies` against `silva_species` — a separate,
species-annotated SILVA file — immediately after `assignTaxonomy`. MetaFlux calls it
with DADA2's own defaults apart from `tryRC`, which follows `taxonomy.try_rc` (the same
setting `assignTaxonomy` uses), so a species is added only on an unambiguous exact match;
ASVs with no match, or with more than one, keep an empty species slot.

`addSpecies` returns the bare epithet (`subtilis`), not the full binomial. The 16S
pack sets `prefix_style: bare`, which tells the taxonomy-string builder two things:
add the rank prefixes itself, and render the last slot as a Genus + species binomial
by gluing the genus back on. A finished 16S lineage therefore reads:

```text
k__Bacteria;p__Bacillota;c__Bacilli;o__Bacillales;f__Bacillaceae;g__Bacillus;s__Bacillus subtilis
```

Under `sintax` there is no species rank at all. The SINTAX database is converted from
the same toGenus training set and carries only the ranks down to genus (`d:` to `g:`;
seven on SILVA 144, six on 138.2), so the
`Species` column of `taxon_seq_table.txt` is `NA` for every ASV and no `s__` segment
appears in the taxonomy string. Species-level 16S calls require `method: rdp`.

!!! tip

    Species assignment from a single 16S region is exact-match only and often absent —
    that is the method, not a failure of the run. Where species resolution is the point
    of the experiment, the two protein-coding markers are the alternative:
    [gyrB](gyrb.md) has higher intra-genus resolution than 16S, and
    [rpoB](rpob.md) assigns far more ASVs to species than 16S V3–V4 does.

Note that the first rank is written `k__` under both methods, even though SINTAX
labels it `d:` internally: the prefixes are keyed to what the rank *means*, not to the
letter the database happens to use. A `keep: [k__Bacteria]` token therefore behaves
identically whichever method is selected. Under SILVA 144 that first slot is still the
domain; SILVA's own Kingdom rank is in `taxonomy_lineage_full.tsv` (see
[above](#the-kingdom-rank-removed-for-classification-restored-next-to-it)).

## Keeping and discarding taxa

The keep and discard lists have no built-in default — they are commented out in the
shipped config on purpose, so a run that forgets them applies no tokens rather than
silently applying another marker's. The organelle filter (below) is on by default and
needs no tokens, so it still runs. The recommended 16S starting point:

```yaml
taxonomy:
  filter:
    enabled: true
    keep:    [k__Bacteria, k__Archaea]
    discard: [o__Chloroplast, f__Mitochondria]
```

- `keep` runs first and defines what survives. `[k__Bacteria, k__Archaea]` keeps
  prokaryotes and drops both off-target eukaryotic hits and ASVs that stayed
  unclassified at kingdom level.
- `discard` then prunes what is left. Chloroplast and mitochondrial 16S are amplified
  by most universal primers from any plant, algal or host material in the sample, and
  they are ribosomal enough to pass Metaxa2 — the filter is where they go.
- Lab and kit contaminants a negative control revealed can be added to `discard` as
  further genus tokens, e.g. `[o__Chloroplast, f__Mitochondria, g__Ralstonia]`.
- ASVs that Metaxa2 calls mitochondria or chloroplast are removed as well
  (`filter.organelles: metaxa2`, the default; `off` keeps them), and every ASV is still
  listed, with Metaxa2's call, in `06.taxonomy/asv_table_unfiltered.txt` — see
  [the organelle filter](../taxon-filter.md#the-organelle-filter-organelles).

Each token is matched against a whole rank segment of the taxonomy string, so
`g__Bacillus` matches a genus named exactly that and never a substring somewhere else
in the lineage (a SILVA 144 `--other` suffix is ignored, see above). If the filter
removes every ASV, MetaFlux stops with an error instead of writing an empty table —
that combination nearly always means the tokens belong to a different marker.

`discard` also looks one step past the reported taxonomy. The reported lineage stops at
the last rank whose confidence reaches `min_boot` / `sintax_cutoff`, and mitochondrial
16S often stays below that at order and family level although the classifier's best
hit is clearly *Mitochondria* — plant and algal mitochondria are diverse, and SILVA 144
holds many more of them than 138.2. Such an ASV is reported as `p__Pseudomonadota`,
escapes `f__Mitochondria`, and turns up in the abundance table and, as a very long
branch, in the tree. So an ASV is also discarded when its best hit carries a discard
token at the token's own rank with at least `filter.discard_min_support` support
(default 50, in percent; SINTAX confidences count ×100). Each such ASV is listed in the
log with its support. `discard_min_support: null` switches the check off.

In practice the ASVs this check removes are mitochondrial 16S that the classifier could
place only to phylum or class: their nearest reference is a mitochondrion, and Metaxa2
calls nearly all of them mitochondrial too. Full behaviour on
[Keeping and discarding taxa](../taxon-filter.md).

!!! note "Plant mitochondria that no token catches"

    In plant-associated samples, some mitochondrial ASVs get past every token, most often
    with `rdp` (on either SILVA release) and with `sintax` on SILVA 138.2; `rdp` can report
    them as *Enterobacterales*, down to family. Their best hit is not *Mitochondria*, so
    neither the tokens nor the best-hit check can catch them. Metaxa2 still calls them
    mitochondrial, and the organelle filter removes them on that call, so at the default
    settings they are gone whichever classifier and release you use. With
    `filter.organelles: off` they stay in the table.

## What a 16S run produces

The final tables are in `06.taxonomy/`:

| File | Rows | Contents |
|---|---|---|
| `asv_table.txt` | `ASV_#` IDs | per-sample counts plus a `taxonomy` column |
| `asv_table_seqs.txt` | ASV sequences | the same table, keyed by sequence |
| `taxon_seq_table.txt` | `ASV_#` IDs | one column per rank (Kingdom…Species) plus the sequence |
| `asv_table_unfiltered.txt` | `ASV_#` IDs, every ASV that reached the filter | the same counts and `taxonomy`, plus Metaxa2's call (`metaxa2_origin`) and `filter_status`: `kept`, or the filter step that removed the ASV |
| `taxonomy_lineage_full.tsv` | `ASV_#` IDs | SILVA 144 only: Domain, the restored Kingdom, Phylum…Species, the SILVA-style lineage and a `kingdom_note` |

Alongside them, `stats/trunclen.json` records the truncation decision,
`stats/dada2/asv_length_stats.json` and `asv_length_hist.png` record the ASV length
distributions before extraction, after extraction and after the length filter, and
`stats/read_tracking.txt` shows how many reads each sample kept at every stage. The
full layout is in [Output files](../../reference/output.md).

16S is also the only marker with an optional phylogeny stage: switch it on and the run
adds a maximum-likelihood tree of the retained ASVs, exported unrooted, for Faith's PD
and UniFrac in R. It is off by default and adds nothing to the run when it stays off.
See [Phylogeny (16S)](../phylogeny.md).
